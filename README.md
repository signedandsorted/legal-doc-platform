# Legal‑Doc AI Platform

A self‑service web application that lets UK clients:

* Draft a will (with capacity‑vault video proof)
* Create lasting Power‑of‑Attorney (property & health)
* Run a probate self‑service module (generate PA1A, IHT400, etc.)
* Pay for the service via Stripe

All documents are generated by an on‑premise LLM (Ollama `llama‑2‑13b‑chat‑qa`).  The platform is **client‑first** – the user does all data entry and video recording; a solicitor only reviews the final draft.

## Quick start (Docker Compose)

```bash
git clone <repo‑url>
cd legal‑doc‑ai‑platform
cp .env.example .env   # edit the values (Stripe keys, DB password, etc.)

docker compose up -d    # starts db, backend, frontend, ollama
```

The UI will be reachable at `http://localhost:3000` (Next.js) and the API at `http://localhost:8000`.

## Architecture

* **Frontend** – React/Next.js (Docker image `frontend/Dockerfile`).
* **Backend** – FastAPI (Docker image `backend/Dockerfile`). Handles:
  * Draft endpoints (`/draft/will`, `/draft/poa`, `/draft/probate`).
  * Stripe checkout (`/payments/create-session`).
  * Webhook (`/webhook/stripe`).
  * Video upload (`/capacity/video/upload`).
  * Solicitor‑review integration via ClawLink.
* **Database** – PostgreSQL (encrypted at rest).
* **LLM** – Ollama container exposing `http://ollama:11434`.
* **Object storage** – Local S3‑compatible bucket under `~/.openclaw/media/` (mounted into containers).

## Building & running locally

```bash
docker compose build
docker compose up -d
```

## Deploying to production

* Use a TLS‑terminated reverse proxy (NGINX, Traefik) in front of the services.
* Store secrets in a vault (e.g., HashiCorp Vault) and inject them at container start.
* Enable HTTPS for the Stripe webhook endpoint.
* Configure a nightly cron job (`automation/delete_old_vault.sh`) to purge capacity‑vault data after 5 years.
